# Review UI/UX, chức năng, khả năng mở rộng (2026-11-10)

Tiếp nối [ui-ux-audit-2026-10-r3.md](ui-ux-audit-2026-10-r3.md). Vòng này nhìn lại cả ba mặt
trên HEAD `9a20724`, thêm phần **khả năng mở rộng** mà các vòng trước chưa đụng tới.

## Cách kiểm

| Hạng mục | Cách đo |
|---|---|
| Nền | `npx tsc --noEmit` sạch, `npm run build` sạch, vitest 1951/1951 |
| Render | Bản build trong Chromium headless (Playwright), file `dist/` phục vụ bằng chặn request — không mở port, không mở cửa sổ |
| Ma trận | 22 tool + Settings × sáng/tối × 1200×800; 8 tool ở 800×600; EN và VI |
| Chỉ số | Lỗi console, request ra ngoài, control không tên, tràn ngang, chữ bị cắt (`scrollWidth > clientWidth`) |
| Hiệu năng | Bơm ~2,6 MB một dòng (JSON minified) vào ô nhập, đo long task; chuyển tab đi rồi quay lại |
| Dữ liệu hỏng | Ghi giá trị sai kiểu vào `devtool-favorites`, `-features`, `-workspaces`, `-tool-order`, `-locale` |

**Giới hạn:** không chạy trong Tauri thật (titlebar macOS/Windows, hộp thoại file, sidecar) và
không kiểm phần Rust. Số đo hiệu năng dùng sự kiện input tổng hợp với dữ liệu một dòng — là
trường hợp xấu nhất; phép thử với dữ liệu nhiều dòng không chạy xong nên không có số.

Sạch: 0 lỗi console, 0 request ra ngoài, 0 control thiếu tên, không tràn ngang; dữ liệu lưu
bị hỏng không còn làm vỡ shell.

## Tóm tắt

Nền móng tốt và đang được giữ kỷ luật (registry tự phát hiện plugin, guard test giữ vi phạm
thiết kế ở 0). Hai việc đáng lo nhất:

1. **App treo hàng chục giây khi dán dữ liệu lớn**, và treo lại mỗi lần quay về tab đó.
2. **Mô hình lưu trữ** (một file JSON, nạp hết vào RAM) không chịu được dữ liệu tích luỹ.

## Khả năng mở rộng

1. **Lưu trữ.** Mọi thứ nằm trong `app-settings.json`, mỗi key một chuỗi JSON, nạp hết vào
   RAM lúc khởi động (`lib/persistentStore.ts`). Input của tool được lưu nguyên (bản dán
   2,6 MB → 2,9 MB mỗi tool). Lịch sử API Client tới 50 × 256 KB. `clockify:entries` không
   debounce, không cắt bớt: mỗi thay đổi serialize lại cả mảng. Hướng: tách dữ liệu lớn ra
   file riêng theo tool (hoặc SQLite), đặt trần cho input được lưu.
2. **Nhóm sidebar viết cứng** trong `lib/toolGroups.ts`, không nằm trong manifest → plugin
   cài thêm không vào được nhóm. Route `/` đang thuộc về Cron Generator.
3. **Quyền plugin không phải sandbox** (đã ghi trong `platform/types.ts`). Với Marketplace,
   bước xem manifest khi cài là hàng rào duy nhất.
4. **File quá lớn:** `editor/store.ts` 1622 dòng, `RunnerDialog.tsx` 1537, `PipelineTab.tsx`
   1464, `NetworkTools.tsx` 1414, `Settings.tsx` 1208, `App.tsx` 1123.
5. **Thư viện trùng vai:** `dayjs` + `date-fns`, `xml2js` + `fast-xml-parser`, `uuid` +
   `nanoid`; `reflect-metadata` không được import ở đâu trong `src/`; `lodash`, `cheerio`,
   `jwt-decode` mỗi cái dùng ở 1 file.
6. **Khởi động:** 93 request, ~2 MB, 84 file JS cho màn đầu; `main.tsx` import 30+ file CSS
   font, kể cả JetBrains Mono chỉ Text Editor dùng mặc định.
7. **Test:** jsdom được tạo 183 lần, chiếm 51% trong ~106 s (vitest gợi ý `pool: 'vmThreads'`).

## Thứ tự nên làm

1. Chặn treo khi input lớn (hai mục P1 ở trên).
2. Tách lưu trữ dữ liệu lớn khỏi `app-settings.json`.
3. Nhãn, mô tả, từ khoá tiếng Việt trong manifest + tìm kiếm bỏ dấu.
4. Đưa nhóm sidebar vào manifest; tách crate cho `devtool-mcp-server`.
5. P3 còn lại theo tool.
